# 多维分层基准数据集构建

## 概述

为了严密且全面地评估智能体在转录调控分析流程中的任务规划、工具编排以及长文本上下文处理能力，我们构建了一个包含 **366 个独立测试用例** 的多维分层基准数据集。该数据集的设计兼顾了真实世界交互的多样性与生物学逻辑的复杂性，具体由四个层级的评估模块构成。

## 数据集总览

| 模块 | 名称 | 用例数 | 核心评估维度 |
|------|------|--------|-------------|
| T1 | 多难度合成任务集 | 50 | 任务规划与工具编排 |
| T2 | 单流程子任务集 | 166 | 细粒度原子操作精准度 |
| T3 | 复杂生物学推理任务集 | 50 | 高阶逻辑推理与自主决策 |
| T4 | 纯工具依赖型二分类推理评估集 | 100 | 多步工具链调用与数据整合 |

**总计: 366 个测试用例**

## T1: 多难度合成任务集

**全称**: Multi-complexity Synthetic Task Cohort  
**数据文件**: [`T1-0.json`](./T1-0.json), [`T1-1.json`](./T1-1.json)  
**用例数**: n = 50

### 设计目标
为了全面评估系统在面对复杂、异质化真实需求时的稳定性和泛化能力，我们构建了一个包含 50 个不同难度梯度的多复杂度合成任务集。

### 构建方法
该任务集的生成核心是一套基于大语言模型的 **自动化数据合成方法**。为了确保合成的任务既符合生物学逻辑，又具备计算机的可执行性，我们在数据生成过程中融入了严格的领域知识约束。

#### 双核心先验注入
系统在构思任务时会引入两类核心先验：

1. **转录调控专业知识库**: 预构建的领域知识体系
2. **工具功能定义字典**: 涵盖 `bedtools`、`macs2`、`deeptools`、`homer`、`rose`、`beta`、`trapt`、`fimo`、`meme`、`bowtie2`、`samtools`、`picard`、`bamCoverage`、`computeMatrix`、`plotHeatmap`、`plotProfile`、`chipseeker`、`clustProfiler`、`enrichGO`、`enrichKEGG`、`gseGO`、`gseKEGG`、`findMotifsGenome`、`annotatePeaks`、`getDiffExpression`、`aracne`、`viper`、`bedtools intersect`、`bedtools closest` 等 **29 种常用生物信息学工具**的详尽功能定义，并匹配真实的本地文件路径

#### 自底向上的任务构建逻辑
在具体构建单个任务时，自动化脚本通过 **随机采样机制** 从工具字典中抽取一个或多个工具组合，并同步随机匹配相应的数据集（如特定的基因列表或测序文件）。随后，大语言模型以此组合为框架，**反向推导**并生成符合该分析逻辑的自然语言任务描述。

#### 用户画像模拟
为了让最终生成的任务更贴近实际科研场景，系统利用参数化的提示词工程，模拟了不同专业背景用户的语言习惯与思维模式：

- 生物信息学研究员
- 临床医生
- 在校学生
- 其他研究角色

#### 典型生成示例
当脚本随机抽选中 `DESeq2`（差异表达分析）和 `TRAPT`（转录因子富集分析）工具组合，并关联了乳腺癌相关的数据集时，大语言模型会将其转化为一个典型的用户学术需求：

> *"已知本地文件路径为 /data/example/geneset/BRCA.csv，请帮我分析该 BRCA 乳腺癌差异表达基因列表背后的转录调控机制，找出潜在的上游关键转录因子。"*

通过这种方式，数据生成过程能够将生硬的命令行工具调用，自然地转译为高拟真度的用户提问。

### 数据格式
最终，该方法将生成的自然语言任务提示与预期的标准分析步骤进行严格的成对处理，并统一标准化为结构化的 **JSON 格式**输出。

```json
[
  {
    "task": "自然语言任务描述"
  }
]
```

### 示例

| 类型 | 任务示例 |
|------|---------|
| 简单查询 | `使用 /data/example/geneset/BRCA.csv 中的 BRCA 差异表达基因进行通路富集分析` |
| 多步流程 | `I want to analyze differential gene expression in BRCA cancer samples from TCGA database and perform pathway enrichment analysis on the significant genes` |
| 路径+指令 | `/data/trapt/TR_bed/ADNP@Sample_01_0380.bed [分析ADNP转录因子的靶基因和功能注释]` |

## T2: 单流程子任务集

**全称**: Single-step Subtask Cohort  
**数据文件**: [`T2.json`](./T2.json)  
**用例数**: n = 166

### 设计目标
为了对智能体在 **细粒度原子操作** 上的精准度进行量化评估，我们构建了一个包含 166 个独立单步任务的单流程子任务集。

### 构建方法
该任务集的数据主要源于系统在执行多步骤分析时的 **真实历史日志**。通过对这些连续运行记录进行深度解析，我们系统性地剥离了属于宏观规划或多轮对话的冗余信息，从而精准地抽取出执行流程中的核心单步动作。

#### 四大基础操作类别
抽取出的核心动作被归纳为四大基础类别：

| 类别 | 描述 |
|------|------|
| **数据获取** (Data Acquisition) | 从数据库或文件系统读取原始数据 |
| **数据预处理** (Data Preprocessing) | 格式转换、质量控制、过滤清洗 |
| **分析计算** (Analysis & Computation) | 核心生物信息学算法执行 |
| **结果输出** (Result Output) | 生成报告、可视化图表、结果文件 |

#### 自底向上的单步抽取逻辑
在具体抽取单个任务时，系统从一段多步骤的实际分析日志中，**截取某一个特定步骤的输入与输出状态**。为了使这些原子任务贴合真实的日常生物信息学分析场景，我们将抽象的日志记录转化为具体的生物学功能需求。

#### 典型抽取示例
当系统解析一段包含复杂转录因子分析的历史日志时，会准确捕捉到其中利用特定工具切分基因组区域的单步动作，并将其转化为一个具体且具备独立科研意义的用户学术需求：

> *"已知可用数据为 /data/esr1_promoter_regions.bed，请帮我从参考基因组中提取出该雌激素受体1（ESR1）启动子区域的DNA序列。"*

通过这种方式，原本交织在多步工作中的日志记录，被自然地转译为清晰、独立的单步任务。

#### 数据清洗与核验
为了确保评估基准的严密性与数据的纯净度，我们在生成过程中引入了严格的校验与清洗机制：

- 自动检查文件扩展名以及存储路径的合法性
- 剔除所有因运行中断或配置错误导致的无效记录
- 结合人工核验过滤掉存在歧义的数据

### 三元组标准结构
每个被确认合格的子任务都会被严格规范为由以下三者构成的标准三元组，统一以结构化的 JSON 格式输出：

| 组成 | 说明 |
|------|------|
| **需求描述** | 具体的操作指令 |
| **输入数据路径** | 操作所依赖的数据文件 |
| **结果摘要** | 预期输出及验证标准 |

```json
[
  {
    "id": 1,
    "category": "疾病/生物学类别",
    "task": "子任务描述：具体操作指令\n可用数据：数据路径",
    "difficulty": "难度等级"
  }
]
```

### 示例

| ID | 类别 | 任务 |
|----|------|------|
| 5 | 2型糖尿病 | 执行变异与转录因子结合位点的精确重叠分析。可用数据: `/tmp/footprint_eqtl_simplified.bed`, `/tmp/islet_tf_footprints.bed` |
| 16 | ER+乳腺癌 | 提取ESR1靶基因的启动子区域坐标。可用数据: `/data/esr1_target_genes.bed` |
| 4 | (类别二) | Process paired-end ChIP-seq data from `/data/example/ChIP-seq/sample1_R1.fastq` and `/data/example/ChIP-seq/sample1_R2.fastq` with control data for peak calling and quality assessment |

## T3: 复杂生物学推理任务集

**全称**: Complex Biological Reasoning Task Cohort  
**数据文件**: [`T3.json`](./T3.json)  
**用例数**: n = 50

### 设计目标
为了考察多智能体系统在 **缺乏明确指令** 情况下的高阶逻辑推理与自主决策能力，我们由人工专家介入，精心策划并构建了一个包含 50 个高复杂度综合性生物学用例的复杂生物学推理任务集。

### 构建方法

#### "技术信息剥离"策略 (Information Redaction)
在该任务集的构建过程中，我们实施了严格的 **信息剥离策略**：

- **刻意隐去**: 所有具体的软件名称、函数参数及算法暗示
- **仅保留**: 纯粹的生物学背景假设与最终研究目的

#### 设计初衷
要求被评估的系统必须具备深厚的领域知识储备，能够自主将抽象的宏观生物学意图，转化为底层具体可执行的生物信息学方案。

#### 自底向上的任务设计逻辑
在具体设计单个任务时，我们围绕当前前沿的生物学科学假设，构建具有 **多步骤推理空间** 的场景。为了使这些高阶任务呈现出清晰的科学逻辑，我们将研究意图转化为纯粹面向生物学功能探讨的叙述。

#### 典型设计示例
在针对免疫性疾病调控机制的评估用例中，任务被设定为一个具体的学术探究目标：

> *"分析在B细胞中鉴定出的超级增强子区域与已知疾病风险单核苷酸多态性（SNP）的重叠情况，以寻找破坏自身免疫稳态的致病变异。"*

在这种设定下，系统无法直接获得诸如使用特定软件或进行区间求交操作的明确提示，而必须自主理解超级增强子、非编码区突变与自身免疫疾病之间的内在生物学关联，进而独立规划出从数据对齐、位置比对到功能变异注释的完整分析步骤。

#### 人工核验
为了确保该基准测试的严密性与挑战性，所有入选的任务均经过了细致的人工核验：

- 排除所有可以通过简单关键词匹配或单一工具直接解决的常规任务
- 保证输入数据的真实性与分析流程的复杂程度

### 数据格式

```json
[
  {
    "id": 1,
    "category": "疾病/生物学类别",
    "task": "纯生物学目标描述（不含工具/方法提示）",
    "difficulty": "难度等级"
  }
]
```

### 示例

| ID | 类别 | 任务（不含工具提示） |
|----|------|---------------------|
| 1 | 乳腺癌 | 提取乳腺癌（BRCA）肿瘤与癌旁组织对比的差异表达基因集，识别驱动该恶性表型的核心转录调节因子，并输出排名前10的详情文件 |
| 7 | 转移性黑色素瘤 | 获取一份源自黑色素瘤转移灶的未知转录因子结合峰数据，识别其中显著富集的已知基序，以推断其最可能的转录因子家族（如 MITF） |
| 14 | 2型糖尿病 | 对比野生型与 PDX1 敲除型小鼠胰岛细胞的连续信号文件，绘制它们在糖尿病关联靶基因集上的结合信号区域衰减趋势曲线 |

## T4: 纯工具依赖型二分类推理评估集

**全称**: Strictly Tool-Dependent Binary Reasoning Task Cohort  
**数据文件**: [`T4.json`](./T4.json)  
**用例数**: n = 100

### 设计目标
为了专门评测智能体在 **真实工具调用、多源数据整合与多步分析编排** 方面的核心能力，我们构建了一个包含 100 道 "Yes/No" 二分类用例的纯工具依赖型推理评估集。

### 核心设计原则: "绝对防推理" (Anti-reasoning)

该评估集的核心设计原则是 **阻断大语言模型依赖其内置的记忆或通用生物学常识直接推断出答案**。

#### 防泄露措施

| 措施 | 具体实施 |
|------|---------|
| **基因选择** | 彻底剔除 TP53、ESR1 等常见基因，转而采用研究较少的转录因子及罕见通路 |
| **比较逻辑** | 采用信号密度与覆盖率替代易被估算的绝对面积计算 |
| **属性判断** | 将高耗时的全家族属性判断精确收窄为特定双基因对比 |
| **数据来源** | 全面摒弃公认的共调控关系以及经典组织表达特征 |

#### 自底向上的强依赖设计逻辑
在具体设计单个任务时，我们重点强调对工具计算结果的 **强依赖性**，确保不通过实际运行生信工具便无法获得正确结论。为了使这些纯工具依赖的任务具备清晰的科学意义，我们将计算逻辑包装为具体的生物学空间与丰度比较需求。

#### 典型设计示例
在针对染色质三维结构与空间距离的评估用例中，任务被设定为一个具体的数值对比问题：

> *"锌指蛋白家族基因的转录起始位点到最近超级增强子的中位距离，是否小于 HIC2/TRIM66 结构域家族基因？"*

在这种设定下，由于比对的基因和调控元件分布属于冷门区间，系统完全无法通过常识进行逻辑推论，而必须自主调用工具读取基因组坐标文件，精确计算两组基因到超级增强子的空间距离并计算中位数，最后通过数值大小比对给出二分类回答。

#### 覆盖的 9 大转录调控分析原语

| 类别 | 子类型 | 描述 |
|------|--------|------|
| T1-表达比较 | 组织间表达比较 | 判断某转录因子在组织A中的表达是否高于组织B |
| T2-双特征交叠 | 基因组区域重叠 | 判断两类基因组注释区域与遗传变异的重叠碱基对数大小 |
| T3-空间距离 | 结合位点距离 | 计算变异与转录因子结合中心的空间距离 |
| T4-ChIP-seq统计 | 峰值统计 | ChIP-seq 峰的统计与比较 |
| T5-基序分析 | 序列基序 | 基序富集与扫描分析 |
| T6-功能富集 | 通路/GO富集 | 基因集的功能富集比较 |
| T7-基因组注释 | 区域注释 | 基因组区域的分布注释 |
| T8-信号强度 | 信号对比 | 连续信号的定量比较 |
| T9-调控网络 | 网络拓扑 | 调控网络关系推断 |

### 强制工具链要求
T4 任务集强制要求智能体必须通过跨越 **2 至 5 步的真实工具链调用与数据计算**，才能推导出最终的生物学结论（Yes/No）。这种设计排除了所有可以通过参数化记忆直接回答的常规任务，为准确评测智能体在面对复杂真实计算需求时的流程执行与数据处理能力提供了高质量的检验手段。

### 数据格式

```json
[
  {
    "id": 0,
    "category": "T1-表达比较",
    "task": "转录因子ZNF768在胃组织中的表达水平是否高于其在肾脏组织中的表达水平？",
    "difficulty": "基础",
    "answer": "是"
  }
]
```

| 字段 | 说明 |
|------|------|
| `id` | 用例编号 |
| `category` | 所属分析原语类别 |
| `task` | Yes/No 二分类问题 |
| `difficulty` | 难度（基础/中等/高级） |
| `answer` | 正确答案（是/否） |

### 示例

| ID | 类别 | 任务 | 答案 |
|----|------|------|------|
| 0 | T1-表达比较 | 转录因子ZNF768在胃组织中的表达水平是否高于其在肾脏组织中的表达水平？ | 是 |
| 12 | T2-双特征交叠 | 在人类 ZNF132 基因转录起始位点上游 100 kb 至下游 100 kb 范围内，增强子RNA注释区域与常见遗传变异发生重叠的累计碱基对数，是否大于超级增强子区域与常见遗传变异重叠的累计碱基对数？ | 否 |
| 19 | T2-双特征交叠 | 在疾病风险遗传变异 rs1002456（LMX1A 附近）上下游各 100 kb 范围内，转录因子结合位点区域内含有疾病风险遗传变异的累计碱基对数，是否大于表达数量性状位点区域内含有疾病风险遗传变异的累计碱基对数？ | 否 |
