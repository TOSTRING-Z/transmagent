# TransMAgent 人工评估方法论文档

## 一、评估目的与总体设计

为系统性地评估 TransMAgent 在转录调控和生物信息学任务中的综合能力，我们设计了一套基于四位二进制标准的盲审人工评估框架。该评估框架不仅涵盖 TransMAgent，还同时评估了多个基线智能体和前沿大语言模型，以提供充分的横向对比基准。

评估共涉及 **50 个生物信息学查询任务**，覆盖转录调控分析、基因表达数据处理、通路富集分析、表观遗传数据解读等多种典型场景。所有智能体/模型的输出由 **三位独立的领域专家**进行盲审标注，专家对生成方法完全不知情。

---

## 二、评估标准：四位二进制评分体系

评估体系围绕智能体核心推理链条定义了四个二元评分标准（每个标准仅计 0 或 1 分），总分范围为 0–4 分。

### 2.1 事实性与可靠性（Factuality & Reliability, FR）

| 维度 | 说明 |
|------|------|
| **定义** | 评估智能体是否将回答建立在真实数据源之上，是否避免幻觉生成 |
| **通过标准 (1 分)** | 输出明确引用了可追溯的真实实验数据（如 TCGA、ENCODE、JASPAR、TRRUST、GEO 等公共数据库），无编造或无法验证的输出内容 |
| **不通过标准 (0 分)** | 使用模拟数据或无法独立验证的来源；引用不存在的文献或数据；数据溯源链断裂或证据不足 |

**专家评审要点**：
- 数据来源是否有明确的可追溯路径？
- 是否存在编造的数据点、基因名称或统计结果？
- 输出中的数值能否映射到原始数据源？

---

### 2.2 执行与工具利用（Execution & Tool Utilization, ET）

| 维度 | 说明 |
|------|------|
| **定义** | 评估智能体是否正确调用领域特定工具或执行计算代码，且工具调用记录真实可验证 |
| **通过标准 (1 分)** | 工具调用正确，代码实际运行并产生可复现的计算结果，执行日志完整 |
| **不通过标准 (0 分)** | 工具调用失败、核心分析未通过实际运行完成、执行不完整或关键步骤缺失 |

**专家评审要点**：
- 工具调用记录是否与输出内容一致？
- 分析流水线是否完整运行到底？
- 是否存在"声称执行但实际未运行"的情况？

---

### 2.3 任务规划与鲁棒性（Task Planning & Robustness, TP）

| 维度 | 说明 |
|------|------|
| **定义** | 评估智能体是否展现出全面的任务理解、自主规划能力和对错误的恢复弹性 |
| **通过标准 (1 分)** | 任务分解合理，分析阶段逻辑顺序正确，流水线保持连续性，具备错误恢复机制并能从执行失败中恢复 |
| **不通过标准 (0 分)** | 任务分解不足、无连贯计划、流水线在首个障碍处崩溃、无错误恢复路径 |

**专家评审要点**：
- 任务是否被合理分解为可执行的子步骤？
- 当中间步骤失败时，智能体是否能自主调整策略？
- 分析阶段的顺序是否符合领域最佳实践？

---

### 2.4 专业性与可解释性（Professionalism & Interpretability, PI）

| 维度 | 说明 |
|------|------|
| **定义** | 评估输出是否体现领域专业知识，解释是否清晰、结构良好 |
| **通过标准 (1 分)** | 输出反映先验生物学知识，解释与任务匹配且有多方面证据支持，报告结构良好，符合领域标准 |
| **不通过标准 (0 分)** | 解释浮于表面，未充分运用先验领域知识，输出结构混乱，解释与分析证据脱节 |

**专家评审要点**：
- 生物学解释是否建立在领域知识基础上？
- 报告组织是否清晰、逻辑是否连贯？
- 结论是否有分析结果作为支撑？

## 三、评分机制：多数投票制

### 3.1 盲审设计

三位领域专家（Expert A、Expert B、Expert C）独立对每个智能体/模型的每条查询输出进行评审，评审时：

- **完全不知情**：专家不知道每条回复是由哪个智能体或模型生成的
- **独立评审**：三位专家之间无任何沟通或协商
- **四维评分**：每位专家分别对 FR、ET、TP、PI 四个维度进行 0/1 评分

### 3.2 多数投票规则

最终的维度级得分通过**多数投票（Majority Vote）**确定：

- 若三位专家中 ≥ 2 位认为该维度通过，则该维度计 1 分
- 否则计 0 分

每个查询的总分 = FR + ET + TP + PI，范围为 0–4 分。

**示例**：

| 维度 | Expert A | Expert B | Expert C | 多数结果 | 得分 |
|------|----------|----------|----------|----------|------|
| FR   | 1 (Pass) | 0 (Fail) | 1 (Pass) | 2 Pass / 1 Fail | **1** |
| ET   | 1 (Pass) | 1 (Pass) | 1 (Pass) | 3 Pass | **1** |
| TP   | 0 (Fail) | 0 (Fail) | 1 (Pass) | 2 Fail / 1 Pass | **0** |
| PI   | 1 (Pass) | 1 (Pass) | 1 (Pass) | 3 Pass | **1** |
| **总分** | | | | | **3** |

## 五、评估任务设置

### 5.1 任务来源

50 个评估查询任务涵盖以下生物信息学领域：

1. **转录因子调控分析**：TF-target 基因预测、结合位点识别
2. **差异基因表达分析**：微阵列/RNA-seq 数据处理
3. **通路与功能富集分析**：GO/KEGG 富集
4. **表观遗传数据解读**：ChIP-seq、ATAC-seq 数据分析
5. **基因集变异分析**：GSVA 等方法的应用
6. **文献检索与知识整合**：PubMed 文献查询与总结

### 5.2 任务分发

每个评估任务以统一的提示格式分发给所有待评估的智能体/模型，确保输入条件完全一致。智能体需要自主完成数据检索、分析执行、结果解释和报告生成的全流程。

## 六、专家评审流程

### 6.1 专家遴选

三位独立领域专家（Expert A、Expert B、Expert C）需满足以下条件：

- 具有生物信息学、计算生物学或相关领域的博士学位或同等研究经验
- 熟悉转录调控分析、高通量测序数据处理
- 具有发表同行评审生物信息学研究论文的经验
- 与评估对象的开发团队无利益关联

### 6.2 评审材料

每位专家收到：

1. 50 个原始查询的完整文本
2. 每个智能体/模型对每个查询的完整输出
3. 评审标准说明文档（即本文档第二、三节内容）
4. 标准化评分表格

**关键盲审保障**：所有输出以随机化顺序排列，移除任何可能标识来源的信息（如工具名称、特有格式标记等）。

### 6.3 评审步骤

1. **培训阶段**：专家熟悉四个评分标准及其操作化定义
2. **独立评审**：每位专家独立完成所有 50 个查询 × N 个智能体的评审
3. **评分提交**：专家提交各维度的 0/1 评分及简要评语
4. **多数投票**：研究者汇总三位专家的评分，按多数规则确定最终得分

## 七、评分数据记录格式

每条评审记录包含以下字段：

| 字段 | 说明 |
|------|------|
| **Task ID** | 查询任务编号（1–50） |
| **Model / Agent** | 被评估的智能体或模型名称 |
| **Expert A — Review** | 专家 A 对四个维度的评审意见及判定 |
| **Expert B — Review** | 专家 B 对四个维度的评审意见及判定 |
| **Expert C — Review** | 专家 C 对四个维度的评审意见及判定 |
| **Score (0–4)** | 多数投票后的最终总分 |

每条专家评论包含对 FR、ET、TP、PI 四个维度的逐一判断，并附有简要理由和整体总结。

**专家评语示例**（Expert A 对某查询中 TransMAgent 的评审）：

> - FR: Data sourced from public databases; traceability confirmed
> - ET: tools correctly invoked; execution log confirmed
> - TP: analysis stages covered in logical order; pipeline maintained continuity
> - PI: output reflects prior biological knowledge; interpretation is task-appropriate and evidence-supported

对应的四维判定分别为：FR=Pass (1)、ET=Pass (1)、TP=Pass (1)、PI=Pass (1)，总分 4。

## 九、方法学优势与局限性

### 9.1 优势

1. **盲审设计**：消除了评审偏倚，确保评分的客观性
2. **多位专家**：三位专家独立评审 + 多数投票，降低了单一评审者主观性的影响
3. **多维标准**：四个维度覆盖了数据基础、工具执行、规划能力和专业素养的完整评价链
4. **精准二进制**：0/1 评分比 Likert 量表更易统一操作化定义，减少评分模糊性
5. **全流程评估**：评估的是端到端的任务完成能力，而非孤立的知识问答

### 9.2 局限性

1. **任务范围**：50 个查询虽然覆盖了主要场景，但无法穷尽生物信息学的所有任务类型
2. **专家数量**：三位专家虽满足统计稳健性要求，但更多专家可进一步提高可靠性
3. **二进制限制**：0/1 评分虽然清晰，但可能无法捕捉部分合格但未达完美的表现差异
